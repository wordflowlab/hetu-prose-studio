# 产品需求 PRD

## 1. 背景与目标

作者通常能判断一段文字是否合意，却未必能预先写出完整的文风规范。一次生成后丢弃反馈，会让下一次任务重新付出解释成本。文风工坊将作者对具体候选的判断整理成可追溯、可修正的偏好，并用于后续创作。

价值不是训练模型或自动模仿某位作者，而是让同一部作品的写作要求持续积累。偏好是可以推翻的创作依据，不是阻断保存的质量门禁。

## 2. 默认旅程

作者向 Codex 描述目标 → 发现插件与方法 → 读取固定原文、已有规划和偏好 → 外部 Agent 准备不同处理方向及宿主候选 → 作者比较和反馈 → 整理偏好候选 → 按当前任务选用 → 局部精修 → 回读成果并继续。

已有原稿可直接反馈与精修；无偏好时可直接开始写作。作者不必先填表、不必生成固定数量的方向，也不必打开 GUI 才能推进。GUI 负责连贯阅读、比较、证据查看及可选编辑。

## 3. 功能范围

| 需求 | 能力 | 首版完成条件 |
| --- | --- | --- |
| PS-01 | 方案与历史 | 当前小说下创建、查找、固定修订读取、比较与导出；不同作品相互隔离 |
| PS-02 | 偏好规则 | 区分作者声明与 Agent 推导；支持待选、启用、停用、编辑及移除；默认限当前作品 |
| PS-03 | 可追溯依据 | 规则关联固定正文或候选选区；原文引述、字节边界及摘要由程序核对 |
| PS-04 | 不同叙事方向 | 记录视角、信息顺序、对白／动作等处理差异和代价，引用宿主候选，不另存全文 |
| PS-05 | 局部精修 | 固定原文及允许区间，预览替换结果，验证区间外原字节不变；候选写入与采纳复用宿主 |
| PS-06 | 写作上下文 | 按本次目标选择启用规则、必要资料及前文；展示字符与字节预算、裁剪和缺口 |
| PS-07 | 规则冲突 | 保留相反偏好及适用范围，作者或当前任务明确取舍，不能静默最后写入者优先 |
| PS-08 | 接续与恢复 | 原键查询、CAS、响应丢失恢复、关闭重开、停用后历史导出 |
| PS-09 | 包内方法 | Codex 在既有连接中发现 Skill，能覆盖校准、比较、精修、续写与异常恢复 |
| PS-10 | 作者工作面 | 偏好、候选比较、局部差异、上下文与历史；浅暗、窄窗、键盘和完整异步状态 |

## 4. 数据与操作边界

正文、不可变草稿、公开意见、正式设定、任务及作者采纳由宿主维护。插件持有偏好、证据关联、候选的专业比较说明与精修核对记录。原文只在必要的只读结果中呈现，不能落成插件第二份正文数据库。

偏好启用表示本次方法配置，不表示正文已采纳、稿件已定稿或作者授权付费生成。外部 Agent 根据当前会话决定生成和取舍；宿主继续核验任务、范围、固定输入与费用。

## 5. 非功能要求

- 公共 TypeScript SDK、受管 Node 后端与 React 视图；插件不依赖宿主私有包、Rust FFI 或任意本机文件路径。
- 专业对象遵守宿主512 KiB预算与最多100个来源引用；大作品按任务范围拆分，不能截断后伪称完整。
- 字节选区采用宿主 `byte_start`／`byte_end` 的 UTF-8 半开区间；中文、CRLF、空白及组合字符不作隐式归一化。
- 偏好与方向来自明确来源或 Agent 判断；未知、未读与未核对状态不可显示为通过。
- 不承诺固定 Token 节省、文风分数或平台过审；预算测量区分字符、字节、真实 Token 与费用。

## 6. 成功判据

隔离小说完成“第一轮候选 → 作者反馈 → 偏好 → 第二轮局部返工 → 下一章上下文”并可原键恢复。作者能从任一规则回到依据，目标选区外字节不变，正文只有宿主作者决定能够采纳。专业动作、CLI/MCP与工作面读取同一固定成果。
