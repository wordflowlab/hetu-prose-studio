# Skill 与机器协作方案

## 1. 接入与职责

同包提供 `hetu-prose-studio` Skill，经河图 `contributions.skills` 注册。Codex使用既有河图接入套件，通过 `hetu.plugins.inspect`、`capabilities` 和 `invoke` 的 `skills.read` 动态读取。此路径不要求安装同名Codex插件，不承诺控制客户端原生Skill选择器。

入口方法负责按“偏好校准／候选比较／选区精修／下一章接续”路由；实际动作、Schema及效果由当前包能力发现提供。操作地图由正式清单生成，不能维护另一份参数事实源。

## 2. 固定输入与正文接续

1. 固定当前WorkRef、management_ref、插件包和能力摘要；读取原稿、已有专业方案及所需规划。已有长篇按实际阅读范围工作，不以目录代替整书阅读。
2. 候选使用宿主不可变草稿或创作任务结果。Core已为不可变草稿提供证据文稿身份；仅在实际发现和回读可用时将该固定文稿作为插件来源。不能把候选先采纳进正文来满足比较需求。
3. 插件核对来源、UTF-8区间及引文，保存规则或比较说明。公开反馈继续使用宿主任务反馈；规则只引用必要依据和意见身份，不复制整套意见系统。
4. 局部替换预览只返回候选内容与差异，保存参考稿走宿主任务／草稿合同；插件不能直接保存正式正文。宿主入口不够时先补核心及公开Schema，不创建私有旁路。
5. 作者采纳、定稿和费用沿宿主合同另行决定；回读真实结果后组织下一轮上下文。

## 3. 方法质量

少量但叙事决策不同的方向优于机械凑数。偏好描述具体写法，不用“更高级、更细腻”等不可执行评价。一次反馈不足以证明跨场景普适；记录适用人物、任务与反例。作者可撤回规则，Agent不得用统计分数否定作者判断。

上下文先呈现选用规则，证据按需要补读；关键剧情需要原文时不能以节省Token为由省略。字节／字符预算与真实Token、模型费用分开记录。

## 4. 动作与恢复

所有写动作记录完整原输入与operation_key；结果未知先查原操作，明确not_found后才按原输入执行。CAS冲突读取新基线并形成明确差异，不自动改写目标。升级或停用后重新发现，旧包不能继续新调用。

机器验收在同一Codex会话完成安装后发现、方法读取、固定小说、规则与候选、局部精修、返工和下一章准备；CLI/MCP相互回读。GUI仅承担可视化验收，不补缺失业务入口。
